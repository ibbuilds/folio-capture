# UI relevance and differentiation: every concept in the existing atlas

This is the recognition part of the research. It revisits all **68 existing concepts**, preserves their definitions, adds chronology, and states what kind of UI evidence is actually available. It does not approve labels or classify a capture.

The vocabulary includes complete visual identities, narrower materials, cultural references and contextual names. A specific name with no reviewed production UI should remain a research lead; a useful general direction may have older roots and no single invention date. Read the [history](ui-history.md) and [timeline](timeline.md).

## Evidence levels

Visually reviewed interface/hero/section: direct inspection of a published static frame. Reviewed concept/diagram: illustrative material or UI proposal, without verified production behavior. Platform/project account: native implementation or intent documented by its creators. Archive collection: specific historical interfaces are indexed, but unseen members receive no visual claim. Cultural/community context: real terminology with an unverified representative UI corpus. Adjacent example: supports a related trait, not the exact aesthetic attribution.

The prose criteria below are operational research interpretations. Source wording remains separate; related neighbors are not aliases. No score represents measured classification accuracy.

## Pixel / arcade

**Historical position:** 1980s game/bitmap references; web cases 1996–2005.

**Recognize:** Pixel-constructed imagery and period-game graphics organize the presentation. Supporting relationships: Intentional pixel artwork; Period-game vocabulary; Consistent graphic rhythm.

**Do not confuse with:** Retro GUI / desktop nostalgia; Webcore / old-web nostalgia; Kidcore. Counterexamples: Low-resolution damage; One pixel icon.

**UI evidence:** visually-reviewed-interface. The 1980 ordering denotes a reference-era bin, not the invention of pixel art or a first web deployment.

**Sources:** [AD01](https://blog.adobe.com/en/publish/2021/05/25/explore-the-lighthearted-retro-futurism-of-vintage-vaporwave-design), [R01](https://www.archive.rhizome.org/), [H45](https://www.webdesignmuseum.org/exhibitions/pixel-art-in-web-design), [H46](https://www.webdesignmuseum.org/gallery/eboy-1999).

**Dated anchors:** 1999: Inspected eBoy web example ([H46](https://www.webdesignmuseum.org/gallery/eboy-1999)).

## Flat

**Historical position:** Planar predecessors; modern UI movement documented in early 2010s.

**Recognize:** Planar interface graphics use little simulated physical depth. Supporting relationships: Planar fills/forms; Minimal relief; Type/color/spacing hierarchy.

**Do not confuse with:** Semi-flat / selective depth; Minimal / minimalist; Neobrutalism. Counterexamples: Minimalism inferred from flatness; Invisible actions accepted automatically.

**UI evidence:** platform-primary-documentation. Flat surfaces existed earlier. Metro, iOS 7, minimalism and the whole Material system are not aliases for flat design.

**Sources:** [N04](https://www.nngroup.com/articles/flat-design/), [M01](https://learn.microsoft.com/en-us/archive/msdn-magazine/2011/december/windows-phone-how-to-translate-common-design-principles-to-the-windows-phone), [A02](https://www.apple.com/newsroom/2013/06/10Apple-Unveils-iOS-7/), [H30](https://blogs.windows.com/windowsdeveloper/2010/03/18/windows-phone-7-series-ui-design-interaction-guide/).

**Exact naming variants proposed in the atlas:** flat design.

**Dated anchors:** 2013-06-10: iOS 7 announcement as one major UI milestone ([A02](https://www.apple.com/newsroom/2013/06/10Apple-Unveils-iOS-7/)).
